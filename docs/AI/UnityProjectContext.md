# Unity project context

Inspected on 2026-10-27 on `LevelDesign` (base commit `1830228`). Project root: `src/Fireline`.

- **Confirmed environment:** Unity 6000.6.1f1; URP and Visual Effect Graph 17.6.0; Input System 1.20.0; Cinemachine 6.6.0. Graphics settings use a URP asset; both 2D and Universal renderer assets exist. Do not replace pipeline settings to add hose effects.
- **Gameplay:** MonoBehaviour components in `Assets/_Scripts` compile into `Fireline.Gameplay`. `Fireline.Shared` is a local package at `src/Shared/Fireline.Shared/Runtime`; it contains engine-independent health, steering, and infrastructure rules. No active real-time networking framework was identified in the inspected hose code.
- **Hoses:** `HoseLoadout` enables one of StandardHose, MistHose, JetHose on the player. `HoseWeapon.Spray` runs from the player controller in physics steps; it owns 2D wall raycasts, rectangular enemy/fire overlap queries, water application, and revival. JetHose has a shot cooldown and applies damage immediately per pulse. Preserve these gameplay semantics when changing presentation.
- **Hose VFX:** `Resources/HoseVfx/HoseVfxLibrary.asset` owns shared appearance settings. Version-three stream is one continuous mesh particle: `HoseStreamRibbon` maintains its advancing front, parabolic drop, ground-clearance limit, and short release fade. A separate droplet system sheds from the visible curve. Jet emits one pointed spear per shot; jet and mist graphs were preserved during the motion upgrade. `HoseGraphVisual` binds library controls, muzzle pose, range, and contacts to the graphs; stream splashes/steam wait for visible arrival. Gameplay damage/extinguishing still use the original physics timing. `HoseVfxAssets` upgrades through Unity's internal Editor graph model while retaining GUIDs. See `docs/hose-vfx.md` for tuning and the six focused integration/rendering tests. Unity's `aliveParticleCount` is sampled asynchronously about once a second; use rendered output when validating immediate changes.
- **Coordinates:** Gameplay lies on XY. `TiltedView` defines a 30-degree camera tilt and the direction off the ground. Muzzle visuals may be raised; hose queries project the muzzle back to the ground. Use these conversions for impact and steam placement.
- **Fire:** `Game.Runtime.FireZone` owns health and an extinguished UnityEvent. On this branch its assigned fire visual expects a MeshRenderer with `_FlameLength`. Some existing FireZoneTests still construct a sprite/particle-era visual without that renderer; their assumptions need separate review before treating them as a reliable baseline.
- **Assets:** `_Scenes`, `_Prefabs`, `_VFX`, `Settings`, and `_Scripts` hold first-party content. `Player.prefab` has all three nozzles. Shader-based fire art and legacy ParticleSystem water art are already present.
- **Scenes:** EditorBuildSettings lists BasicScene, Jake-Player, and StringReverseScene with all entries disabled. An enabled startup build scene is therefore unresolved; preserve the level designer's open scene.
- **Conventions:** Four-space C#, Allman braces, private serialized fields with tooltips, read-only properties, direct component ownership; gameplay types are partly global and partly in `Game.Runtime`. Runtime and test assemblies are separated.
- **Tests:** PlayMode tests under `Assets/Tests/PlayMode` in `Fireline.Gameplay.Tests`; .NET tests under `src/Shared/Fireline.Tests`. CI builds/tests the shared .NET solution, not the Unity scenes.
- **Tooling:** Unity CLI is installed, but the project has no Pipeline/MCP bridge. The user chose file/log-based work. Editor log: `src/Fireline/Logs/Editor.log`. Baseline includes Burst compiler named-pipe errors. Unity's Roslyn compiler and generated Bee response files can validate C# independently without replacing Editor assemblies.
- **Constraints:** Preserve scenes, prefab GUIDs, serialized names, and gameplay authority. Do not install a bridge/package without authorization. Hose VFX authoring uses only the already installed VFX package.
